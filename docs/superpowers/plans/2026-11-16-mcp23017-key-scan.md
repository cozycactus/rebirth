# MCP23017 Key Scan and Step Buttons 8/16 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive the PR #10 board: scan the 8 x 10 key matrix with two MCP23017 (0x22, 0x23) instead of the TCA8418, read steps 8 and 16 from a third MCP23017 (0x24), and keep GPA7/GPB7 of every expander as outputs.

**Architecture:** A small driver `key_scan.c` knows the two scanner chips (configure, check, select a column and read the rows). `panel_input.c` keeps its API and runs the scan one bus step per UI pass, debouncing each key only at its own samples. `mcp23017.c` becomes a two-chip step row that reads only when a 20 ms sample is due and proves each chip's configuration after every sample. Core 1 is not touched.

**Tech Stack:** C11, Raspberry Pi Pico SDK 2.2.0 (RP2040, I2C0 at 400 kHz), CMake; host tests are plain C executables under `test/` run by CTest, with fakes in `test/fakes`.

**Spec:** `docs/superpowers/specs/2026-11-16-mcp23017-key-scan-design.md` (register values, canary rule, scan steps, health rules, contract, timing). Hardware source: `hardware/schematic/README.md` on branch `session-panel-pcb` (decisions 10, 11, "Interfaces the firmware relies on").

## Global Constraints

- Core 1 code, locks and interrupts are not changed. Core 1 never touches I2C.
- `panel_event_t`, `panel_input_init/poll/next/resync` keep their signatures; `ui.c`, `flash_storage.c`, `test_ui.c` and `test_storage.c` need no change beyond a comment.
- Every I2C transfer, initialisation included, uses `i2c_write_timeout_us` / `i2c_read_timeout_us` with 2000 us and checks the exact byte count; a register read is a 1-byte pointer write with `nostop = true`, then the read with `nostop = false`. `key_scan_init` does not call `i2c_init` (`mcp23017_init` brings the bus up).
- No IODIR write ever sets bit 7 of either port on 0x20, 0x22, 0x23 or 0x24.
- At most one of the ten matrix columns is low whenever U801's rows are read.
- Each input chip's canary (IODIR on 0x22/0x23, IPOL on 0x20/0x24) is its first configuration write and is never written again outside configuration; it is read back after the data it vouches for.
- `panel_input_poll` performs at most one scan step (at most 4 transfers) per call, apart from a configuration attempt (6 writes).
- `PANEL_DEBOUNCE_MS` = 5; a key's state changes only in the pass that sampled its column.
- Press-to-event <= 15 ms for every column and every phase of the 20 ms and 33 ms tasks in the host loop model (Task 2).
- `hardware/` is not changed. No `#error` for DAC gain 2 (the task requires the gain-2 build).
- Host tests pass under CTest and under the CI sanitizer build; every new executable gets `add_test`; unused static functions left behind by a task are deleted in that task. The firmware builds without warnings with `-DREBIRTH_CV_DAC_GAIN=1` and `=2`.

## Review Focus

- No phantom press from a scanner chip that resets at any transfer (init included) or a transfer that fails, lands partly or returns short — Task 2.
- A held SCENE/MUTE key must not ghost into other columns when a U802 write fails after the chip latched it, or across a resync while COL8/COL9 is selected — Task 2.
- Keys and PLAY held through a resync, and keys held at power-up, never fire; a key released during a stall presses again — Task 2.
- A reset U703 (before or inside its read) must not press steps 8 or 16; a missing U703 must not take steps 1-7/9-15 down; a chip whose reads fail makes no long press — Task 3.

## Working Method (every task)

Write the listed tests first; build the target and see it fail to compile/link or fail its checks; implement; run the task's checks; commit only the task's files with `git add <files> && git commit -m "<message>"`. Names of helpers, internal structure and code layout are the implementer's.

**Interfaces:**
- Produces:
  ```c
  // key_scan.h
  #define KEY_SCAN_ROW_ADDR 0x22   // U801: GPA0-6 = ROW0-6, GPB0 = ROW7, GPB1-7 = COL0-6, GPA7 = COL7
  #define KEY_SCAN_COL_ADDR 0x23   // U802: GPA0 = COL8, GPA1 = COL9, other pins open
  #define KEY_SCAN_ROWS 8
  #define KEY_SCAN_COLS 10
  bool key_scan_init(void);                          // six writes (spec order); selection unknown
  bool key_scan_check(bool *intact);                 // false = I2C error; *intact = U801 IODIR+IPOL and U802 IODIR as written
  bool key_scan_column(uint8_t col, uint8_t *down);  // false = I2C error (selection then unknown)
  ```
  Register values, write order, deselect-before-select and the selection rule are in the spec ("Scan driver"). `*down` bit r = ROW r low.
- Fake (`fake_key_matrix.h`), which also defines `i2c_init`, `i2c_write_timeout_us`, `i2c_read_timeout_us` for addresses 0x22 and 0x23 only:
  ```c
  void fake_matrix_reset(void);                  // both chips at power-on values, no key closed, no fault, counters 0
  void fake_matrix_chip_reset(uint8_t addr);     // brown-out of one chip: IODIR = FF/FF, every other register 0
  extern bool fake_matrix_key[8][10];            // closed keys [row][col]
  extern bool fake_matrix_float_low;             // a floating pin reads low (default true: worst case)
  extern int fake_matrix_txn;                    // transfers so far (failed ones included), 1-based numbering
  extern int fake_matrix_fail_txn;               // this transfer fails once (0 = none)
  extern int fake_matrix_fail_from;              // this transfer and all later ones fail (0 = none)
  extern int fake_matrix_fail_bytes;             // a failing write first applies this many data bytes (0 = none, -1 = all)
  extern int fake_matrix_short_txn;              // this transfer returns one byte less than asked, data applied/filled up to there
  extern int fake_matrix_reset_txn;              // before this transfer, fake_matrix_chip_reset(fake_matrix_reset_addr)
  extern uint8_t fake_matrix_reset_addr;
  extern int fake_matrix_reset_in_read_txn;      // this read: chip resets after its first data byte, the rest reads 0xFF, full count
  extern unsigned fake_matrix_wire_bytes;        // bytes on the wire, address bytes included
  extern bool fake_matrix_clock;                 // each transfer advances timer_hw->timerawl by its wire time (22.5 us/byte)
  extern int fake_matrix_low_column;             // column (0-9) low at the last U801 row read, -1 none
  uint8_t fake_matrix_reg(uint8_t addr, uint8_t reg);
  ```
  The fake has its own copy of the PR #10 pin map (not the driver's constants). A column is low only when its pin is an output with OLAT 0, high when an output with OLAT 1, floating when an input. A row pin reads low when a closed key sits in a low column; otherwise high when it is an input with its pull-up; otherwise (no pull-up, i.e. after a reset) `fake_matrix_float_low ? 0 : 1`. IPOL applies to input pins. An output pin reads its OLAT; a floating column pin reads the floating level. Sequential register pointer (BANK 0). Every transfer CHECKs: timeout 2000 us; address 0x22/0x23; a 1-byte write before a read has `nostop` true, the read and every register write have it false; no IODIR write with bit 7 set on either port; at most one of the ten columns low at every U801 GPIO read.

Behaviour per the spec ("Step row"): per-chip configuration (IPOL first, then OLAT 00/00, IODIR, GPPU; 7F/7F on 0x20, 03/00 on 0x24; each a 3-byte write), per-chip `configured`/retry/`rebaseline`/`trusted`; a sample is read only when `now - _debounce_ms >= MCP_DEBOUNCE_MS` or a rebaseline is pending; per chip: GPIO pair read, then IPOL pair read; the GPIO bytes are used only if IPOL matches; IPOL mismatch -> reconfigure + rebaseline that chip's bits; failed read or configuration -> keep that chip's bits, untrusted (no long press for its bits) until a good sample, reconfigure before its next read; step word = `(A20 & 0x7F) | (B20 & 0x7F) << 8 | (A24 & 1) << 7 | (A24 & 2) << 14`. `MCP_CHECK_MS` and `MCP_RESET_SUSPECT_KEYS` go.
