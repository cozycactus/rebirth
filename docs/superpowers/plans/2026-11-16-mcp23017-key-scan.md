# MCP23017 Key Scan and Step Buttons 8/16 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive the PR #10 board: scan the 8 x 10 key matrix with two MCP23017 (0x22, 0x23) instead of the TCA8418, read steps 8 and 16 from a third MCP23017 (0x24), and keep GPA7/GPB7 of every expander as outputs.

**Architecture:** A small driver `key_scan.c` knows the two scanner chips (configure, check, select a column and read the rows). `panel_input.c` keeps its API and runs the scan one bus step per UI pass, debouncing each key only at its own samples. `mcp23017.c` becomes a two-chip step row that reads only when a 20 ms sample is due and proves each chip's configuration with every sample. Core 1 is not touched.

**Tech Stack:** C11, Raspberry Pi Pico SDK 2.2.0 (RP2040, I2C0 at 400 kHz), CMake; host tests are plain C executables under `test/` run by CTest, with fakes in `test/fakes`.

**Spec:** `docs/superpowers/specs/2026-11-16-mcp23017-key-scan-design.md` (register values, scan steps, health rules, timing). Hardware source: `hardware/schematic/README.md` on branch `session-panel-pcb` (decisions 10, 11, "Interfaces the firmware relies on").

## Global Constraints

- Core 1 code, locks and interrupts are not changed. Core 1 never touches I2C.
- `panel_event_t`, `panel_input_init/poll/next/resync` keep their signatures; `ui.c`, `flash_storage.c`, `test_ui.c` and `test_storage.c` need no change beyond a comment.
- Every I2C transfer, initialisation included, uses `i2c_write_timeout_us` / `i2c_read_timeout_us` with 2000 us and checks the exact byte count; a register read is a 1-byte pointer write with `nostop = true`, then the read.
- No IODIR write ever sets bit 7 of either port on 0x20, 0x22, 0x23 or 0x24.
- At most one key-matrix column is low whenever U801's rows are read.
- `panel_input_poll` performs at most one scan step (at most 4 transfers) per call, apart from a configuration attempt (5 writes).
- `PANEL_DEBOUNCE_MS` = 5; a key's state changes only in the pass that sampled its column.
- Press-to-event <= 15 ms for every key and scan phase in the host loop model (Task 2).
- `hardware/` is not changed. No `#error` for DAC gain 2 (the task requires the gain-2 build).
- Host tests pass under CTest and under the CI sanitizer build; unused static functions left behind by a task are deleted in that task. The firmware builds without warnings with `-DREBIRTH_CV_DAC_GAIN=1` and `=2`.

## Review Focus

- No phantom press from a scanner chip that resets or a transfer that fails at any step of a scan — Task 2.
- A held SCENE/MUTE key must not ghost into other columns when a U802 write fails after the chip latched it — Task 2.
- Keys and PLAY held through a resync, and keys held at power-up, never fire; a key released during a stall presses again — Task 2.
- A reset U703 must not press steps 8 or 16; a missing U703 must not take steps 1-7/9-15 down — Task 3.

**Interfaces:**
- Produces:
  ```c
  // key_scan.h
  #define KEY_SCAN_ROW_ADDR 0x22   // U801: GPA0-6 = ROW0-6, GPB0 = ROW7, GPB1-7 = COL0-6, GPA7 = COL7
  #define KEY_SCAN_COL_ADDR 0x23   // U802: GPA0 = COL8, GPA1 = COL9, other pins open
  #define KEY_SCAN_ROWS 8
  #define KEY_SCAN_COLS 10
  bool key_scan_init(void);                          // see spec; forgets the selected column
  bool key_scan_check(bool *intact);                 // false = I2C error; *intact = both IODIR as written
  bool key_scan_column(uint8_t col, uint8_t *down);  // false = I2C error or column readback mismatch
  ```
  Register values, write order, deselect-before-select and the column readback are in the spec ("Scan driver"). `*down` bit r = ROW r low.
- Fake (`fake_key_matrix.h`), which also defines `i2c_init`, `i2c_write_timeout_us`, `i2c_read_timeout_us` for addresses 0x22 and 0x23 only:
  ```c
  void fake_matrix_reset(void);               // both chips at power-on values, no key closed, no failure, counters 0
  void fake_matrix_chip_reset(uint8_t addr);  // brown-out of one chip: IODIR = FF/FF, every other register 0
  extern bool fake_matrix_key[8][10];         // closed keys [row][col]
  extern bool fake_matrix_float_low;          // a floating pin reads low (default true: worst case)
  extern int fake_matrix_txn;                 // transfers since reset (failed ones included)
  extern int fake_matrix_fail_txn;            // this 1-based transfer fails once (0 = none)
  extern int fake_matrix_fail_from;           // this transfer and all later ones fail (0 = none)
  extern bool fake_matrix_write_lands;        // a failing write is still applied by the chip
  extern unsigned fake_matrix_wire_bytes;     // bytes on the wire, address bytes included
  extern bool fake_matrix_clock;              // each transfer advances timer_hw->timerawl by its wire time (22.5 us/byte)
  extern int fake_matrix_low_column;          // column low at the last U801 row read (-1 none)
  uint8_t fake_matrix_reg(uint8_t addr, uint8_t reg);
  ```
  The fake has its own copy of the PR #10 pin map (not the driver's constants). A column is low only when its pin is an output with OLAT 0, high when an output with OLAT 1, floating when an input. A row pin reads low when a closed key sits in a low column; otherwise high when it is an input with its pull-up; otherwise (no pull-up, i.e. after a reset) `fake_matrix_float_low ? 0 : 1`. An output pin reads its OLAT; a floating column pin reads the floating level. Sequential register pointer (BANK 0, wraps after 0x15). Every transfer CHECKs: timeout 2000 us, address 0x22/0x23, no IODIR write with bit 7 set on either port, at most one column low at every U801 GPIO read.

### Task 2: Panel input on the scanner; remove the TCA8418

**Files:**
- Modify: `include/panel_input.h` (`PANEL_DEBOUNCE_MS 5`, drop `PANEL_CHECK_MS`, comments for the new rules), `src/panel_input.c`, `test/test_panel_input.c` (rewritten on `fake_key_matrix`), `test/CMakeLists.txt` (`test_panel_input` from `test_panel_input.c` + `fakes/fake_key_matrix.c` + `fakes/fake_hardware.c` + `key_scan.c` + `panel_input.c`), `CMakeLists.txt` (drop `src/tca8418.c`), `src/ui.c` (the `panel_input_init` comment)

**Interfaces:**
- Consumes: `key_scan.h` (Task 1).
- Produces: the unchanged `panel_input.h` API. Behaviour per the spec ("Panel input"): 11-step free-running scan (step 0 = `key_scan_check`, steps 1-10 = columns 0-9), one step per poll after PLAY; `see()`/`settle()` only for the sampled column's 8 keys; any failure, reset or readback mismatch -> scanner unconfigured, `raw = accepted || suppressed` and `since = now` for every key, scan restarts at step 0, re-init before the next sample (an attempt after a failed one waits `PANEL_RETRY_MS`); resync and init take every key as held (`raw = true`, `accepted = false`, `suppressed = true`), drop the ring, `forget_play()`, restart at step 0, no I2C in resync. Ring of 32; a full ring leaves the change pending until the column's next sample.

### Task 3: Step row on U701 and U703

**Interfaces:**
- Produces: the unchanged `mcp23017.h` API (`init`, `poll`, `resync`, `get_buttons`, `read_raw`, `step_buttons_t`). Behaviour per the spec ("Step row"): per-chip configuration (OLAT 00/00, IODIR, GPPU, IPOL = 7F/7F on 0x20 and 03/00 on 0x24, each a 3-byte write, OLAT first), per-chip `configured`/retry/`rebaseline`; a sample is read only when `now - _debounce_ms >= MCP_DEBOUNCE_MS` or a rebaseline is pending; each chip read is 8 bytes from 0x0C; GPPU mismatch -> reconfigure + rebaseline that chip's bits; failed read -> keep that chip's bits, reconfigure before its next read; step word = `(A20 & 0x7F) | (B20 & 0x7F) << 8 | (A24 & 1) << 7 | (A24 & 2) << 14`. `MCP_CHECK_MS` and `MCP_RESET_SUSPECT_KEYS` go.
