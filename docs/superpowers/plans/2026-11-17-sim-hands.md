# Hands on the Simulator Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two realistic 3D hands over the simulator's drawn panel perform every finger action of the artist's score, with a toggle, checks in `sim/check.sh`, and a measured frame cost.

**Architecture:** A vendored three.js bundle and an embedded hand model; `handrig.js` builds, poses and fits one hand (Node and browser); `handplan.js` turns `show.actions` into per-hand timelines; a driver in `handrig.js` samples a timeline into poses; `handlayer.js` draws them in a WebGL canvas over `#device`; `app.js` loads it lazily and owns the toggle.

**Tech Stack:** plain classic-script JavaScript (no modules), three.js 0.187.0 bundled with esbuild 0.25.0, Node for checks (`node:assert`), Python 3 for the asset build, headless Chrome (puppeteer-core) only for local verification.

**Spec:** `docs/superpowers/specs/2026-11-17-sim-hands-design.md` (read it first; this plan does not repeat its reasons).

**Branch:** `claude/sim-hands` (from `origin/master`). The worktree holds an uncommitted throwaway prototype (`sim/web/handsgl.js`, `sim/web/handmesh.js`, `sim/web/three.js`, edits in `sim/web/index.html` and `sim/web/app.js`); Task 1 removes it. ## Global Constraints

- Classic scripts only, no `import`, no `fetch`, no workers: the page must work from `file://`.
- `sim/web/index.html` keeps exactly its eight `<script src="…">` tags (`sim/publish.sh` fails otherwise). The hands' scripts are loaded from `app.js`.
- New page files are named `[a-z]+.js` (plus `notices.txt`) and are listed in `PAGE_FILES` in `sim/publish.sh`.
- Global names: `THREE`, `HAND_MODEL`, `HandRig`, `HandPlan`, `HandLayer`. Never `Hands` or `hands` (taken).
- Each new script ends with the repository's export idiom: `if (typeof module !== 'undefined' && module.exports) module.exports = api; else root.X = api;` with `root` = `typeof window !== 'undefined' ? window : globalThis` (see `sim/web/artist.js:1459-1461`). `three.js` sets `globalThis.THREE`.
- Pinned sources: three 0.187.0, esbuild 0.25.0; Godot XR Tools commit `6fc5361db295c12b5e51ee5b9fee09751a4458e7`, folder `addons/godot-xr-tools/hands` (CC0 1.0, DigitalN8m4r3; mesh from MakeHuman, CC0). MIT and CC0 notices kept in the files and in `sim/web/notices.txt`.
- World units are page units: 1400 per side of the panel square = 300 mm (`UNITS_PER_MM = 1400 / 300`). Page point (u, v) is world (u, −v, 0); +z is up out of the plate.
- Control tops above the plate (mm): pad 5.6, scene 4.6, mute 3.5, step 4.0, PLAY 5.0, encoder knob 14.5 (20 mm across).
- Eye: world (700, −2100, 4600); camera orientation identity (looks down −z, up +y), frustum shifted, never `lookAt`.
- Hand scale: the model × 0.92 (an 18.7 cm hand).
- `sim/web/artist.js`, `sim/test/artist_check.js` and the device's behaviour do not change.
- Every task: tests first and seen failing; `node sim/test/hands_unit.js` and (once it exists) the whole `sim/check.sh` pass before the task's commit; one commit per task; files outside the task's list untouched.

## Review Focus

1. The toggle switched off and on while a step is held in the middle of a set: no control left ringed or pressed, and the hands come back with a finger already on the held step (Task 8, browser steps 5–6).
2. The artist stopped mid-gesture by a click on the panel (`takeOver`) or by "Выключить и включить": no exception, the hands leave within 300 ms, a later show plans from scratch (Task 8, browser step 7).
3. The page from `file://` with WebGL2 unavailable or a script failing to load: the ring works as today and the console has no uncaught error (Task 8, browser step 8).
4. A narrow window (the 900 px single-column layout) or a resize mid-set: the canvas follows `#device` and fingertips stay on the drawn controls (Task 8, browser step 9).
5. A hidden tab coming back mid-set (`MAX_STEP_S` clamps the device's catch-up): the hands never show a contact ahead of the light and do not replay a backlog (Task 6 test `draw time never passes an unprocessed event`; Task 8, browser step 10).

### Task 3: Fitting — one fingertip, several, the pinch, clearance

**Files:**
- Modify: `sim/web/handrig.js`, `sim/test/hands_unit.js` (section "fit").

**Interfaces:**
- Consumes: Task 2.
- Produces, on `Rig`:
  - `rig.armDir(target) -> THREE.Vector3` — from the shoulder (left `(350, −2000, 1633)`, right `(1050, −2000, 1633)`) to the target, flattened, then pitched 20° down.
  - `rig.place(finger, target, dir)` — root rotation from `dir` and up `+z`, then translated so `rig.pad(finger)` equals `target` exactly.
  - `rig.fit(targets, opts) -> { ok, residualMm: {finger: mm} }` — `targets` `{finger: Vector3}`; per finger 3 angles (spread, proximal flex, intermediate flex with distal = 2/3 of it; thumb: metacarpal two axes, proximal and distal shared), damped least squares (λ = 0.1, ≤ 30 iterations, numeric Jacobian), limits spread ±20°, flex 0–95° (thumb metacarpal −30–60°); an outer loop of ≤ 4 rounds moves the root (translation, yaw, pitch) by the mean residual; `ok` iff every residual ≤ 1 mm. `opts.dir` seeds the yaw; `opts.freeYaw` lets the outer loop turn the hand up to ±100° (clip copy).
  - `rig.pinch(enc, twistDeg) -> { ok, residualMm }` — thumb and index pads on the knob's rim (radius 10 mm, opposite points at angle `twistDeg`, 8 mm above the plate).
  - `rig.clear(active)` — for fingers not in `active`, curl toward `fist` (thumb toward `lift`) by bisection until no `CLEARANCE` vertex of that finger is below `PANEL.topAt`; then, if any palm vertex is still below, raise the root and refit `active` (≤ 3 rounds).
  - `rig.violations() -> [{vertex, mm}]` — `CLEARANCE` vertices below the plate or the control top under them, deepest first.
  - `HandRig.POSES` = `point`, `relax`, `fist`, `lift`, `pinch` (the prototype's `point`, `relax`, `fist`, `lift`; `pinch` thumb `[20, 20, 10]`, index `[0, 25, 30, 15]`, the others as `fist`).
